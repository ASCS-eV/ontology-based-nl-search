# Research behind the conference story

Checked **24 September 2026**. This is a targeted primary-source review, emphasizing relevant 2025–2026 publications. It is not an exhaustive systematic review or a claim that no later related paper exists. Publication dates below come from the papers or their proceedings, not search-engine crawl timestamps.

[Conference deck](./) · [Speaker guide and demo](./conference)

## Recommendation

Build the talk around **“It produced a scenario—but is it the one I meant?”** A highway cut-in is a shared engineering task for asset discovery and scenario creation; it is not evidence of a connected selected-road handoff. Recent work supports discussing ontology grounding, structured scenario descriptions and feedback together. That connection is our synthesis of the literature, not a conclusion experimentally established for this repository.

Position the project as two concrete applications of a controlled-generation pattern: an ontology-driven search path and an independent OpenSCENARIO authoring path with visible intermediate representations and diagnostics. The [recorded technical rehearsal](./rehearsal) now supplies a concrete inspection decision: country-only search filtering and an authored road that does not meet the requested three-lane condition. Slides 4–6 label these as recorded excerpts; the other illustrative diagrams remain schematics. Reserve comparative accuracy, time savings, safety improvements and cross-domain generality for a dedicated evaluation. No external paper's benchmark numbers should appear as prototype results.

## Supporting references for questions

**TARGET — Yao Deng et al., Traffic Rule-Based Test Generation for Autonomous Driving via Validated LLM-Guided Knowledge Extraction.** Published online 9 May 2025; IEEE Transactions on Software Engineering 51(7), July 2025, pp. 1950–1968. A peer-reviewed journal paper using a compositional DSL, validated knowledge extraction and synthesized simulator scripts. It is useful context for structured representations and separate syntax/semantic checks. Its traffic-rule-derived tests and ADS evaluation have a different scope from asset retrieval and general scenario authoring. [IEEE record](https://ieeexplore.ieee.org/document/10998949/), [DOI](https://doi.org/10.1109/TSE.2025.3569086).

**Txt2Sce — Pin Ji et al., Scenario Generation for Autonomous Driving System Testing Based on Textual Reports.** arXiv preprint, 2 September 2025; no peer-reviewed venue was established in the primary record checked. Converts textual accident reports into OpenSCENARIO and uses scenario mutations for downstream testing. This directly motivates standard-format scenario artifacts, while differing from the typed-scene boundary used here. Treat it as related work, not evidence that all generated files run or that this prototype reconstructs accidents. [arXiv record](https://arxiv.org/abs/2509.02150).

**SPARQL-LLM — Panayiotis Smeros et al., Real-Time SPARQL Query Generation from Natural Language Questions.** arXiv preprint, 16 December 2025; primary record labels it “Under Review.” Describes metadata indexing, prompt construction, query generation/execution and evaluation of runtime/cost as well as answers. It supports considering latency and deployment constraints when evaluating NL access to graphs. Its direct query-generation/federation approach differs from this repository's constrained slots and deterministic compiler. [arXiv record](https://arxiv.org/abs/2512.14277).

**Performance and Limitations of Fine-Tuned LLMs in SPARQL Query Generation — Thamer Mecharnia and Mathieu d’Aquin.** GenAIK workshop proceedings, January 2025, pp. 69–77. Examines direct NL-to-SPARQL generation and its limitations on benchmark datasets. Useful background for explaining why the prototype makes the intermediate contract explicit; it is not a controlled comparison with this prototype. [ACL Anthology](https://aclanthology.org/2025.genaik-1.8/).

## Standards: be exact about the version and the claim

ASAM lists **OpenSCENARIO XML 1.4.0**, released **19 May 2026**, as its current release. The standard describes dynamic scenarios and can be used alongside road-network descriptions. ASAM explicitly cautions that identical scenario descriptions do not ensure identical results across simulators. Use that point on slide 6 to distinguish a conforming document from a behavioral or safety result. [ASAM standard page](https://www.asam.net/standards/detail/openscenario-xml/).

The current repository pins **OpenSCENARIO 1.3 / XSD 1.3.0** in `packages/authoring-wasm/versions.json`. The engine's own release identifier is not the OpenSCENARIO schema version. The deck therefore names the supported pin instead of implying support for the latest standard.

## Evaluation worth proposing on stage

Use a fixed schema/catalog snapshot and a small expert-authored set of search requests and scenario intents. Measure interpretation agreement, unsupported-request detection, gate outcomes including skipped checks, execution in a pinned simulator, latency and engineer task completion. Include ambiguous and unsupported prompts. Compare the full workflow with the existing manual workflow; evaluate compiler determinism separately from model variability. Publish the prompts, versions and evaluation criteria before making improvement claims.
